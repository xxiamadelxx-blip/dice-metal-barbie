# M5 offline Blender asset proof (D20 + D6)

This tool builds **real 3D stone surface geometry with Boolean digit-contour cuts**, and separate thin metallic 3D digit inlays. It uses Blender and DejaVu Serif installed in GitHub Actions; there are no downloaded textures, external API costs or proprietary source assets.

- Source: `tools/blender/generate_die_assets.py`.
- Cloud build: `.github/workflows/blender-assets.yml`. Its artifact contains two glTF binaries, two actual Blender renders and a face-map manifest.
- Coordinate contract: Godot Y-up vertices -> Blender Z-up -> glTF Y-up. D20 12 collision-aligned base vertices radius 0.88, 20 face IDs and same opposite-pair 1..20 assignment; D6 exact 1.22 unit side and original six labels.
- This is a **staged external visual asset experiment**, not an already approved Godot integration. The existing Jolt collision shapes, RNG, outcome and UI are not touched. First inspect generated GLBs and PNG render evidence, then integrate models as only graphics, verify normals and face index alignment with physical bodies, and rerun all physics and 720x1280 Godot and Android renderer tests.
- The GLBs use standard metallic/roughness Principled materials. Production PBR texture/normal/roughness baking and mobile draw-call/triangle optimization are future hard gates. The proof does not claim true photorealism.
- Artist must reject any visibly distorted glyph cut, collision-bevel mismatch, gapped inset, unreadable number, overdraw or unacceptable phone FPS. PR #23 stays DRAFT and issue #24 stays OPEN.

## Gauntlet material pass: embedded procedural PBR textures (2026-10-10)
- Blender now generates deterministic 256x256 low-contrast obsidian **albedo, roughness and tangent-space normal PNGs** from periodic multi-frequency smooth noise, creates stone spherical UVs after the exact Boolean cut, connects the image nodes to Principled BSDF, and exports them in GLB. This is **offline procedural map generation, NOT a high-poly-to-low-poly Cycles normal bake**. Do not describe it as that.
- `validate_glb.py` requires PNG sources, embedded GLB image/texture objects, `TEXCOORD_0` on the cut stone mesh, and material references to all three texture channels. `tests/engraved_assets.gd` then verifies that the running Godot scene applies the imported texture channels via a controlled lit material override. A green Blender generator alone is not acceptable unless the native scene imports the refreshed GLBs.
- Approved sculpt geometry, original Jolt collision, numeric face IDs, body mass and critical aura logic remain unchanged. Texture seams, visibility and Android GPU are still visual/phone acceptance gates. The Blender workflow compares binaries and only pushes regenerated GLBs to the **approved draft feature branch** if the validated bytes differ; `main` stays untouched.

## Blender learning pass and white-stone regression fix
The material audit used [Blender 4.1 glTF exporter manual](https://docs.blender.org/manual/en/4.1/addons/import_export/scene_gltf2.html), [Blender 4.0 Normal Map manual](https://docs.blender.org/manual/en/4.0/render/shader_nodes/vector/normal_map.html), [Khronos glTF 2.0 spec](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html), [Blender Guru texturing course](https://www.blenderguru.com/posts/how-to-texture-in-blender-full-course) and [MK Graphics procedural-to-image texture bake tutorial](https://www.youtube.com/watch?v=zFLxWRfs4Ak). Documentation and video course outlines were researched directly, without smry; no claim of watching every online Blender video. The existing PNG method is offline procedural generation, not Cycles high-poly baking.

**Root cause of failed Blender render:** prior albedo linear values around 0.8 drove the GLB Base Color input and overrode the darker BSDF constant. The preview contained pale silver faces. Source albedo has been corrected to ~0.088 linear charcoal/blue and its mean checked in the manifest; roughness is now closer to the physically plausible polished stone range ~0.36, non-color channel G. The Godot PBR override uses white albedo factor with a dark texture to avoid accidental second multiplication. Normal and roughness remain Non-Color; tangent normals are consumed via a Normal Map node. A physical Android device is still required for final performance and color acceptance.

## D8 and D12 authored-geometry pass (Gauntlet)
The approved D8 and D12 now use the same **Blender Boolean-cut lettering, 3-segment edge bevel, bronze inset, 256x256 PBR material and Godot scene import** pipeline as D6/D20. Their face-index values follow the canonical Godot octahedron (D8 i XOR 7 = 9) and dual-of-icosahedron dodecahedron (D12 indexed primal-vertex antipodes = 13). All four models are source-generated; GLBs are validated and pinned on the draft branch by the guarded Blender Action. D4 remains deliberately separate because apex-number reading requires duplicated digits on three sloping faces, not one per opposing facet.

New practical uses of the additional toolchain: **MeshLab** runs through Xvfb on the exact final Boolean stone exported as OBJ by Blender, checks it can import and re-export real PLY geometry; **ImageMagick** inspects all three generated texture map dimensions and colorspace. Both outputs/logs are included in CI artifacts. Neither modifies Jolt physics. This is a geometry-import proof, not a guarantee of watertightness or mobile FPS; later `Godot native visual QA`, physics tests and handset verification remain separate gates.

## D4 apex-number engraving via Blender, not conventional face mapping
D4 is a tetrahedron resting on one face, and the number comes from its **top apex**. For each of four apexes, `apex+1` is cut into each of the **three adjacent faces**, producing **12 physical engraved glyphs**, not four incorrect face numbers. Geometry and placement exactly follow `src/core/tetrahedron.gd` (four normalized ±1 vertices at radius 0.98; `lerp(apex, face_center, .48)`). Blender carries out a single Boolean subtract, joins 12 bronze inlays, and exports `d4_boolean_engraved.glb`. MeshLab verifies the QA-only PLY transfer; Godot retains original `TetrahedronCollision` and `top_vertex` result logic. CI validates the four apex labels and 12 imprints. As with all other art, native screenshots and device tests must be assessed before release.
